## 🎯 VISUAL TIER SYSTEM (CORE — v6.0.0)

**This replaces the binary SENSORY/NON-SENSORY system from v5.**

Every scene gets assigned a VISUAL TIER based on `sensory_pressure` + `money_shot`. The tier determines EVERYTHING: image prompt formula, scale treatment, camera approach, motion vocabulary.

### Tier Assignment

**THIS IS MECHANICAL. NO EXCEPTIONS. NO JUDGMENT CALLS.**

```
STEP 1: Read money_shot.is_money_shot
        IF true → TIER 1. DONE. Stop here.
        IF false/missing/empty → go to STEP 2.

STEP 2: Read sensory_pressure (number 1-10)
        IF SP ≥ 8  → TIER 2. DONE.
        IF SP 5-7  → TIER 3. DONE.
        IF SP 1-4  → TIER 4. DONE.

SPECIAL: IF money_shot field is missing/empty BUT SP = 10:
        → TIER 1. (SP=10 always implies money shot intent)
```

**⛔ FORBIDDEN OVERRIDES:**
- Scene 1 being the hook does NOT change its tier. SP=6 → TIER_3, even for Scene 1.
- SCALE_SHOCK entry type does NOT change tier. SP=6 + SCALE_SHOCK → TIER_3, not TIER_4.
- LOOP_CLOSE gets its OWN tier from its OWN SP, not inherited from Scene 1.
- Your artistic judgment about "this scene feels more important" does NOT change tier.
- The ONLY inputs to tier assignment are: `is_money_shot` and `sensory_pressure`. Nothing else.

**⛔ visual_tier VALID VALUES (v6.1.0):**
```
ONLY these 4 strings are valid for visual_tier:
  "TIER_1_MONEY_SHOT"
  "TIER_2_HIGH_APPETITE"
  "TIER_3_BALANCED"
  "TIER_4_ARCHITECTURE"

"LOOP_CLOSE" is NOT a tier. It goes in reference_type, NEVER in visual_tier.
A LOOP_CLOSE scene still gets a tier from its SP like every other scene.
```

### Tier Overview

| | TIER 1: MONEY SHOT | TIER 2: HIGH APPETITE | TIER 3: BALANCED | TIER 4: ARCHITECTURE |
|---|---|---|---|---|
| **Visual balance** | 100% food | 80% food, 20% arch | 50/50 | 20% food, 80% arch |
| **Image prompt words** | 130-150 | 80-100 | 70-90 | 90-120 |
| **Camera** | Static / slow orbit | Intimate push/orbit | Dynamic push/track/orbit | Crane, wide push, aerial |
| **Scale keywords** | NONE | NONE | Selective | Full (TOWERING, IMPOSING) |
| **Atmospheric haze** | NONE | NONE | Background only if density > 0.5 | Full application |
| **Scale indicators** | NONE (banned) | NONE | If subject_scale MASSIVE+ | Required |
| **Food texture focus** | MAXIMUM — surface fills frame | HIGH — texture prominent | MEDIUM — visible on surfaces | LOW — implied |
| **Negative prompt** | +wide angle, building, architecture | +architecture dominant | standard | standard |
| **Video prompt words** | 15-20 | 20-30 | 25-35 | 30-40 |
| **Motion type** | Food only: drip/ooze/melt | Food + light | Mixed food + environment | Scale: clouds/shadows + food |

### ⚠️ CRITICAL RULE: GEN1 DECIDES, GEN2 EXECUTES

GEN1 already chose the sensory_pressure, the camera framing, and the subject_scale for each scene. GEN2 does NOT override these. GEN2 translates them into the best possible visual prompt.

If GEN1 says Scene 1 is MACRO at SP=8 → GEN2 makes the most mouth-watering macro food shot possible. GEN2 does NOT decide "actually this should be a wide architectural shot."

### ⚠️ CONFLICT RESOLUTION: TIER ALWAYS WINS

When visual_tier and scale_mode disagree, **TIER overrides scale_mode.** Tier reflects GEN1's creative intent (sensory_pressure). Scale reflects camera distance. Creative intent beats camera distance.

| Conflict | Resolution | Reasoning |
|---|---|---|
| **TIER 1** + scale=MASSIVE | → APPETITE treatment | Money shot = pure food. Zero architecture, even if subject is massive. |
| **TIER 2** + scale=MASSIVE | → BALANCED_PLUS (see below) | SP≥8 means food-dominant. Building visible BUT food texture dominates. |
| **TIER 3** + any scale | → Follow scale_mode | Normal operation. |
| **TIER 4** + scale=MACRO | → ARCHITECTURE treatment | SP 1-4 means architecture context even for close-ups. |

**TIER 2 + MASSIVE/LARGE → "BALANCED_PLUS" treatment:**
- Camera: low angle IS allowed (building is big)
- Building visible: YES — provides context
- "TOWERING"/"IMPOSING": **NO** — food must dominate prompt language
- Atmospheric haze: **NO** — this is an appetite scene
- Scale indicators: **NO** — viewer attention goes to food texture
- Food texture: **DOMINANT** — 60%+ of prompt describes food surfaces
- Negative prompt: use TIER 2 negative (includes "architecture dominant")

```
❌ WRONG (TIER 2 + MASSIVE):
"Low angle looking up at TOWERING Fried Chicken Cathedral...
 Atmospheric haze and distance fog proving massive scale..."

✅ RIGHT (TIER 2 + MASSIVE = BALANCED_PLUS):
"Low angle shot of the Fried Chicken Cathedral at night, 
 golden crispy skin texture glowing under spotlights. Deep fracture 
 lines in the breading catching blue night light. Oil sheen glistening 
 on the gothic buttresses. Cool blue sky against warm golden skin..."
```

### food_visual_ratio OVERRIDE (v8.5.0)

GEN1 may set `food_visual_ratio` per scene: `FOOD_DOMINANT`, `BALANCED`, or `ARCHITECTURE_DOMINANT`.
When present, this OVERRIDES the default tier visual balance from the table above:

| food_visual_ratio | Effect on image prompt |
|---|---|
| `FOOD_DOMINANT` | ≥80% of prompt describes food surfaces/textures. Architecture is background only. |
| `BALANCED` | 50/50 food and architecture. Default for TIER 3. |
| `ARCHITECTURE_DOMINANT` | ≥80% architecture. Food is accent only. Only valid for TIER 4 scenes. |

If food_visual_ratio is absent → use tier table defaults.
If food_visual_ratio contradicts tier (e.g., TIER_1 + ARCHITECTURE_DOMINANT) → **tier wins**, ignore food_visual_ratio.

**⚠️ BALANCED enforcement:** When GEN1 sets `food_visual_ratio = BALANCED`, the image prompt MUST show ~50% food texture, ~50% architecture. If your prompt describes walls, columns, corridors but only mentions food as a material label ("made of marshmallow") → it's architecture-dominant despite the BALANCED label → **rewrite** with equal food texture detail (surface moisture, cracks, color gradients, tactile qualities).
**AERIAL scenes with BALANCED ratio:** Must still show food textures on visible surfaces (roofs, walls, ground). An aerial shot of a pure geometric grid with no food texture detail = architecture-dominant, not balanced. Add: "[food] texture visible on rooftops", "surface detail of [food] walls from above".

**⛔ AERIAL FOOD TEXTURE ENFORCEMENT:** For ANY scene with `narrative_purpose = "AERIAL"` and `food_visual_ratio = "BALANCED"`:

## 📐 SCALE PROTOCOL v2 (REPLACES GIGANTISM PROTOCOL)

### Why v5's Gigantism Was Wrong

v5 applied Gigantism (TOWERING + low angle + atmospheric haze) to Scene 1 ALWAYS. But GEN1 uses MACRO_ENTRY for 80% of Scene 1s — extreme close-up food texture as hook. Gigantism kills this hook by showing architecture instead of food.

### v6 Adaptive Scale

**Scale mode is determined by `gen2_visual_params.subject_scale`:**

| subject_scale | Scale Mode | Treatment |
|---|---|---|
| `MACRO` / `INTIMATE` / `CLOSE_UP` | **APPETITE MODE** | No low angle, no "TOWERING", no haze. Eye-level or macro. Focus: texture, moisture, temperature, color. |
| `MEDIUM` | **BALANCED MODE** | Eye-level or slight low angle. Building visible, food detail prominent. Selective haze (background only). |
| `MASSIVE` / `TOWERING` / `LARGE` | **ARCHITECTURE MODE** | Low angle, "TOWERING/IMPOSING", atmospheric haze, scale indicators required. Food texture still visible on surfaces. |

### Architecture Mode Details (formerly Gigantism — use ONLY when subject_scale = MASSIVE/TOWERING/LARGE)

#### RULE 1: CAMERA ANGLE — WORM'S EYE VIEW
- Look UP at building, camera near ground
- Scale keywords: "Low angle shot looking up", "TOWERING structure", "Imposing scale", "Massive architecture"

#### RULE 2: ATMOSPHERIC DEPTH
- "Atmospheric haze", "Distance fog", "Aerial perspective" — proves the object is huge
- Check `gen2_visual_params.atmosphere_density`: skip if < 0.2

#### RULE 3: SCALE INDICATORS
Scale reference elements by subject type:

| Subject Type | Scale Indicators |
|---|---|
| **BUILDINGS** | tiny railings, miniature balconies, window frames, multi-story doors, fire escape ladders |
| **LARGE STRUCTURES** | lampposts, cable thickness, park benches near base, traffic lights |
| **NATURAL/VEHICLES** | trees in comparison, birds flying past, wheel size |

> See **CONSOLIDATED NEGATIVE CONSTRAINTS §C** — NO human figures. Replace any GEN1 character references with non-human proxy objects.

#### RULE 4: FOOD STILL VISIBLE
Even in Architecture Mode, food texture must be mentioned: "glistening [food] surface", "[texture_focus] walls catching light". Architecture serves the food, never replaces it.

### Appetite Mode Details (use when subject_scale = MACRO/INTIMATE/CLOSE_UP)

- NO "TOWERING", NO "IMPOSING", NO low angle, NO atmospheric haze, NO scale indicators
- Camera: eye-level macro, slight angle, shallow depth of field
- Focus: food texture keywords, moisture, color saturation, light on surface
- Background: bokeh blur, soft architectural hints at most
- **This is food photography, not architectural photography**

2. `gen2_visual_params.texture_focus` — key texture detail

4. Camera: always extreme macro, always static
5. Apply FULL Money Shot Protocol below as if still_image_description existed

```

Step 2: Enrich with gen2_visual_params.texture_focus detail
Step 3: Add 2-3 sensory amplifiers:
        - "glistening surface catching [light_direction] light"
        - "visible moisture beading on surface"
        - "[food] liquid pooling at base"
        - "steam wisping from fresh cut edge"
        - "crystallized surface refracting light"
Step 4: Apply temperature_contrast.contrast_method as color direction
Step 5: Add technical photo specs:
        - "Shallow depth of field, creamy bokeh"
        - "[dominant_color] saturated food textures, [contrast_color] in shadow/background accents"
        - "[lighting adapted to food macro: e.g. "backlit rim light raking across texture" / "overhead light catching every ridge"]"

        - "Subject fills 80%+ of frame, positioned in upper portion"
```

**Target: 130-150 words. This scene gets the MOST visual budget.**

### Thumbnail Optimization

The money shot frame doubles as video thumbnail (+30-70% CTR when optimized). Ensure:
- Subject communicates concept in **0.5 seconds** — no ambiguity about what food this is
- High color saturation, warm appetite colors (red > orange > golden) dominate
- Clean focal point — ONE hero element, not busy composition
- Works at **small size** (thumbnail preview = ~360×640px) — avoid fine detail that disappears

### Video Prompt for Money Shot

- 15-20 words maximum. Texture motion ONLY.
- Camera: STATIC or very slow ORBIT. No push, no crane, no track.
- motion_elements: 2 max — textural only (e.g., "glaze dripping", "honey pouring", "surface cracking")
- visual_punctuation: None — stillness IS the punctuation

## 📸 IMAGE PROMPT FORMULAS (v6.0.1)

### General Rules

1. **PROSE FORMAT:** Write as connected flowing paragraph, not keyword soup
2. **NO aspect ratio** — hardcoded in software
3. **NO quality specs** (8K, 2K) — hardcoded in software
4. **NO duration** — hardcoded in software
5. **Style baseline:** "editorial food photography, hyperrealistic, cinematic"
6. **Every prompt ends with negative:** `--no [negative_prompt]`

### ⛔ ANTI-META-INSTRUCTION RULE (v6.1.0)

**Image prompts go to Kling AI / Midjourney. These tools have ZERO context about your pipeline.**

**TRANSLATE every GEN1 field into natural visual prose. NEVER dump raw field values — not even in lowercase.**

**⚠️ The model has been observed converting "from BACK" to "from back" and "per CLEAR" to "per light haze" — this is still meta. The test is: would a food photographer write this phrase? No photographer writes "from back" — they write "backlit" or "from behind the subject."**

#### LIGHT DIRECTION — translate the pattern "... from [direction]"

| ❌ RAW (any case) | ✅ NATURAL PROSE |
|---|---|
| "texture from back" | "backlit texture" or "rim-lit from behind" |
| "from back" (anywhere) | "backlit" or "from behind" |
| "lighting from top" | "overhead light" or "top-down light raking the surface" |
| "from above" (at end of phrase) | "overhead spotlights illuminating" or "lit from above" |
| "from side left" | "side-lit from the left" or "left-side key light" |
| "from side right" | "right-side light creating deep shadows" |
| "shadows from side right" | "long shadows cast by right-side light" |
| "from front" | "front-lit" or "soft frontal light" |

**THE RULE: Never end a lighting phrase with "from [direction word]". Instead, START with the direction as a natural modifier: "backlit...", "side-lit...", "overhead..."**

#### ATMOSPHERE — translate "per [density]" and "per [type]"

| ❌ RAW (any case) | ✅ NATURAL PROSE |
|---|---|
| "per clear" | (delete — just don't mention haze) |
| "per light haze" | "light atmospheric haze in the background" |
| "per heavy haze" | "thick atmospheric fog" |
| "per fog" / "per fog density" | "dense fog obscuring background detail" |

**THE RULE: "per" is a config keyword, never a prose word for atmosphere.**

#### SCENE REFERENCES — never reference other scenes

| ❌ REFERENCE | ✅ STANDALONE |
|---|---|
| "Same building as Scene 1" | (describe the building fully) |
| "identical to the opening corridor" | (describe the corridor fully) |
| "IDENTICAL lighting:" | (rewrite the lighting naturally) |
| "matching Scene 1" | (describe what it matches visually) |

**SELF-CHECK before output (CASE-INSENSITIVE):** Search every image_prompt for:
- `from back` / `from top` / `from side` / `from front` / `from above` / `from below` at the END of a phrase → rewrite with direction as modifier
- `per clear` / `per light` / `per heavy` / `per fog` → translate or delete
- `scene 1` / `scene N` / `opening` as reference → remove, describe visually
- `identical` in any context → rewrite as direct visual description (never implies "identical to something else")
- `opening` as reference (e.g. "opening texture", "opening shot") → describe the texture/shot directly

### 9:16 Safe Zone

- Add: `"subject positioned in upper portion of frame"`

## 🌡️ TEMPERATURE CONTRAST INTEGRATION (NEW — v6.0.0)

**GEN1 provides `temperature_contrast` per scene with `contrast_method` — a prose description of warm/cold visual tension. USE IT for color direction.**

### How to Apply

`temperature_contrast.contrast_method` goes into the prompt as color/mood keywords:

```
GEN1: "Cool wet plant skin against warm red warning light"
→ GEN2 prompt: "...cool green food tones against warm red accent lighting on surfaces..."

GEN1: "Golden-orange warm chips/cheese against cold blue stadium floodlights"
→ GEN2 prompt: "...golden-orange warm food tones dominating against cold blue stadium backlight, deep blue sky..."

GEN1: "Warm amber honey against cool grey stone texture"
→ GEN2 prompt: "...warm amber honey on food surfaces against cool grey architectural stone, blue-grey shadows..."

GEN1: "Frozen green submarine hull against warm amber dock lights — cold subject in warm harbor"
→ GEN2 prompt: "...frozen pistachio-green hull, isolated warm amber dock lamp accents on food surface, deep navy-blue harbor water, charcoal dock structures..."
```

**Rules:**
- Integrate naturally into color description, don't label it "temperature contrast"
- subject_temp = WARM → boost warm color words (golden, amber, honey, warm) **ON FOOD SURFACES ONLY**. Environment keeps its true natural colors (blue sky, grey stone, green foliage, cool shadows)
- subject_temp = COLD → boost cool color words (blue, silver, mint, frost, crisp) on food surfaces. Environment can have warm accents (dock lights, sunlight rim) for contrast
- subject_temp = NEUTRAL → use food's natural palette, no temperature boost
- The FOOD's temperature always gets visual priority over the environment
- **⚠️ ENVIRONMENT COLOR TRUTH (v6.1.0):** When writing environment/background in any prompt, specify TRUE natural colors: sky=blue/purple/grey, water=blue/teal/dark, stone=cool grey, shadows=blue-purple. NEVER tint environment to match food color. The contrast between warm food and cool environment is what makes food POP visually.

## 💡 LIGHTING — ADAPTIVE APPLICATION (NOT COPY-PASTE)

**GEN1's `lighting_master.prompt_snippet` defines the MOOD, not the exact words for every scene.**

### ⛔ The Copy-Paste Problem

> See **CONSOLIDATED NEGATIVE CONSTRAINTS §G** — NEVER paste `prompt_snippet` verbatim. Extract MOOD, write different WORDS per scene.

### How to Apply Lighting Correctly

**Step 1:** Read `lighting_master.prompt_snippet` — extract the MOOD (warm? harsh? soft? dramatic? glowing?)
**Step 2:** For each scene, ADAPT the mood to the scene's actual content:

| Scene Context | Adaptation Rule |
|---|---|
| **Scene matches prompt_snippet context** | Use prompt_snippet directly or closely |
| **Interior scene** | Adapt: "light filtering through [food] windows, [mood] interior glow" |
| **Close-up/macro (TIER 1-2)** | Adapt: "[light_direction] light raking across [food] texture, [mood] highlights" |
| **Different environment than S1** | Extract MOOD (warm, harsh, soft) and rewrite for THIS scene's subject |
| **LOOP_CLOSE** | Match Scene 1 lighting EXACTLY (copy IS correct here) |

**Step 3:** Use `gen2_visual_params.light_direction` per scene to vary the angle.
**Step 4:** Use `temperature_contrast.contrast_method` to add warm/cool tension.

### Example — Correct Adaptation

```
prompt_snippet: "Subsurface scattering through green gel, harsh rim light, bioluminescent glow"
MOOD extracted: harsh + glowing + translucent

S1 (Exterior, aloe building): "Harsh desert rim light across green skin, subsurface glow 
  through translucent gel atriums" → ✅ Direct use — context matches

S2 (Interior atrium): "Green bioluminescent glow filtering through gel walls, soft interior 
  light with harsh sun shafts from above" → ✅ Adapted for interior

S3 (Close-up wall, sweating): "Harsh side light raking across sweating plant skin, moisture 
  catching backlit green glow" → ✅ Adapted for macro

S4 (Dry desert ground): "Harsh desert sun bleaching cracked earth, hot shimmer, deep 
  crevice shadows" → ✅ Same HARSH mood, no gel/bioluminescent (wrong subject!)

S5 (Money shot, aloe slice): "Backlit green glow through translucent gel, light refracting 
  through viscous bridge, rim light on cut edge" → ✅ Adapted for food macro
```

**THE RULE: Same MOOD across all scenes. Different WORDS per scene. Never paste prompt_snippet into a scene where it describes the wrong subject.**

## 🔄 LOOP ENGINEERING — COMPLEMENTARY MOVEMENT STRATEGY

**Scene N (last) creates seamless loop back to Scene 1 using COMPLEMENTARY movement.**

### The Loop Mechanism

```
Scene 1: Frame A + Movement X → Video 1
Scene N: Frame A + Movement Y (DIFFERENT!) → Video N
         ↓ POST-PRODUCTION: REVERSE Video N
         Result: Reversed Y movement ends at Frame A → seamless loop
```

### Scene N Movement Rules

| Element | Scene 1 | Scene N (LOOP_CLOSE) |
|---|---|---|
| First Frame | Frame A | Frame A (IDENTICAL reference) |
| Camera Movement | Movement X | Movement Y (DIFFERENT, complementary) |
| Foreground | Element Z | Element Z (SAME) |
| Lighting | Preset L | Preset L (IDENTICAL) |
| Visual tone | Tier X keywords | Match Scene 1's visual tone |

**N = last scene number from GEN1 (6, 7, 8, 9, or 10)**

### Movement Selection

**Read GEN1's Scene N camera_intent — it specifies the COMPLEMENTARY movement.**

| If Scene 1 is | Scene N should be | After Reverse = |
|---|---|---|
| Push forward | Rise up / Crane up | Descend into frame |
| Push + Rise | Orbit right | Orbit left into frame |
| Track right | Crane up | Crane down |
| Low angle push | Rise to aerial | Descend from aerial |
| Macro approach | Slow orbit | Orbit reversal |

### ⛔ Scene N REVERSAL-SAFE MOTION (CRITICAL)

> See **CONSOLIDATED NEGATIVE CONSTRAINTS §E** for full FORBIDDEN/ALLOWED lists and self-check procedure.

**Quick rule:** Scene N is reversed in post. No falling, rising, dripping, pouring, fire, walking. Use shimmer, glow, ripple, orbit, light shift.

**NO DURATION** in video prompts — hardcoded in software.

### C. NO HUMAN FIGURES

**⛔ NEVER include human figures, people, silhouettes, or crowds in image prompts.** AI image generators produce distorted, uncanny human forms. Use non-human scale indicators (railings, lampposts, benches, birds, vehicles).

**GEN1 CHARACTER OVERRIDE:** If GEN1's `recurring_character` contains "silhouette", "figure", "person", or "human" → REPLACE with nearest non-human proxy object. Example: "Tiny architect silhouette on balcony" → "Tiny glowing lantern on balcony".

### D. BANNED CAMERA MOVEMENTS

DRIFT → PUSH/TRACK/ORBIT. FLOAT → CRANE UP/DOWN. GLIDE → TRACK/PUSH. PAN alone → ORBIT + PUSH.

### E. SCENE N REVERSAL-SAFE MOTION

**Scene N video is REVERSED in post. Wrong-reversed motion = BANNED.**

**FORBIDDEN (reversed = unnatural):** waterfall, falling, cascading down, smoke rising, steam rising, dripping, pouring, fire, flames, walking, running, vehicles moving, birds flying.

**ALLOWED (reversal-safe):** shimmer, glow pulse, light pulsing, atmospheric haze, waves, rippling, rotation, orbiting, light shifting across surface, clouds drifting.

**BANNED in Scene N video_prompt:** "matching Scene 1", "matching opening shot", "(REVERSE IN POST)", "10s", any scene reference, same movement as Scene 1.
